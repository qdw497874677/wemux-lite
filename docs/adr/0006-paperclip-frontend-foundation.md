# 以 Paperclip 前端为基础替换 Wemux 旧前端

已确认采用 Paperclip 前端为基础改造，而非仅模仿外观或照搬其产品模型：尽量沿用应用壳、导航、设计系统、基础组件和交互模式，路由与数据加载实现经适配核实后复用，业务层遵守 Wemux 的 Project、Workspace、Session、Worker 与 Agent 定义。原因是消除旧前端结构债，而不借界面重写改变既有领域边界；复用 MIT 代码须保留许可声明。

新前端在独立目录开发。删除旧前端的必要条件是全部现有有效功能完成迁移并验证；可分阶段开发和预览，但不得以精简界面为由静默裁剪功能。允许重新组织页面与操作步骤，未完成或不可用的历史入口须单列说明，任何功能废弃须另经用户确认。

从第一天按 Server 与 Worker 双宿主设计，先打通 Server，再完成 Worker 独立工作台，两个宿主都验收后才替换旧版。共用设计系统、会话界面和交互组件；登录、权限、资源发现与集群接入通过明确的宿主接口区分，不让 Worker 独立使用依赖 Server。

允许修复后端真实缺陷、补齐已有功能缺少的 API 和进行必要的兼容性接口调整，但不借前端重写扩展为整个后端重写。迁移期间旧前端仅作为临时入口，不再要求保持其功能回归可用，旧版缺陷不阻断新版实施；不得擅自改变新版权限规则、领域关系或数据含义，破坏数据兼容或需要数据迁移的调整须单独确认，新前端不得以硬编码或吞错掩盖后端缺陷。

页面层重新实现，不复用旧页面、应用壳、路由拼装及混在组件里的权限和状态判断。API 类型、消息事件处理、幂等提交、断线恢复等非 UI 逻辑，经审计与行为测试后可选择性迁入明确的共享模块；新前端不得直接依赖旧前端目录，保证旧目录最终可完整删除。测试保留有效的行为与安全合同，不机械迁移仅锁定旧源码写法的断言。

部署与数据环境只使用现有一套实例，不另建新版预览 Server 或克隆业务数据库。迁移期间同域名同端口共存：根路径继续提供旧版，`/next/` 提供新版，两者连接同一后端并使用同一套账号和数据；旧版不承担新版验收门槛，全部新版能力验收通过后新版移到根路径，再移除旧版。用户明确要求使用真实实例、真实数据和真实 Worker 进行交互验收，并允许修改现有数据，不以模拟后端或单独验收项目替代真实使用验证。历史应用数据的保留限制已被后续允许全量清理的决定取代，具体范围与安全边界见 ADR 0007；不删除源码或外部仓库文件，不执行未授权计费请求。

导航沿用 Paperclip 布局但以 Wemux 的项目与会话为中心：登录后默认项目列表；全局入口为待办、项目、集群、团队、设置。项目内上下文导航组织会话、工作区、任务、画布及项目资源；Agent/Model 管理归于 Worker 能力，创建会话仍可直接选择。审批、活动、连接器等有效功能保留，可调整导航层级，不照搬 Paperclip 的 Agent 业务语义。

移动端适配是交付要求，不能只交付桌面布局；桌面与移动端均纳入切换验收，复杂页面允许调整交互形式，不得以屏幕尺寸为由静默隐藏有效功能。

用户进一步要求参考 Paperclip 的项目管理方式，而不只参考外观。已核查其项目页具有任务列表、工作区、配置等组织方式；具体借鉴的业务流程与领域扩展边界仍待确认，不视为已同意照搬其业务模型。

后续访谈已明确调整常规对话的产品边界：Session 须绑定 Task，见 [0007-task-bound-conversation-direction.md](0007-task-bound-conversation-direction.md)。因此本文最初“不改变既有领域边界”不再适用于 Task 与 Session 的这一关系；对应合同还包括 Team 级协调 Task、同 Session 模型切换、可配置审查及项目级 Agent API；以 ADR 0007 和新版规格为准，其余后端改动边界保持不变。

访谈已获用户整体确认，进入规格落实与实施，见 [新版前端与项目级 Agent 能力规格](../specs/web-next-project-agent-platform.md)。这不代表重写已完成或可以立即删除旧代码；删除门槛仍是全部现有有效功能迁移、双宿主及移动端验收通过。
