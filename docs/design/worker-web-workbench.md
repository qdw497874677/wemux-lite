# Worker 独立 Web 工作台与集群接入

状态：产品方向已确认；M2 W1/W2/W3 已实现并完成自动化与本机 HTTP 冒烟。后续扩展仍以本文边界为设计依据；实现证据见 [M2 验收记录](../acceptance/m2-worker-local-workbench.md)，首批实施契约见 [双宿主首批实施契约](m2-dual-host-contract.md)。依据：[产品方向](../product-direction.md)、[路线图](../roadmap.md)。

## 1. 独立安装、独立使用、按需加入

Worker 安装与集群注册解耦。不配置 Server、不取得集群身份，也应能启动自身 Web/API，使用已安装和认证的 Agent。安装 Worker 不强制安装 Agent。首次本机管理员由本机可信操作初始化，不允许公网首个访问者抢注。

首次进入工作台：登录 → 检测 Agent → 选择允许的本地工作目录与模型 → 创建会话。没有 Agent 时展示检测结果与显式安装/配置指引，不阻止进入工作台。“暂不加入集群”是正常状态，不是错误或每次弹出的强制引导。

本地表示执行发生在 Worker 机器，不表示浏览器必须位于该机器。支持局域网及显式配置的公网 HTTPS 访问；不承诺自动 NAT 穿透。独立模式无须运行精简 Server、伪造 Team/Project，或将全部集群管理模块装入 Worker。

## 2. Worker Web 信息架构

- 会话：最近、搜索、新建、时间线、队列与运行详情。
- 本地工作环境：允许使用的目录、相关会话、共享文件提示。与集群 Workspace/Placement 分开命名与授权；目录不是沙箱。
- Agent 与模型：安装、认证、可执行性、支持操作与诊断。
- 集群连接：可选加入、连接状态、重试、断开与退出。
- 设置：本机管理员、登录会话/API Token、监听与安全配置。

集群页展示未加入状态和“加入集群”主操作；工作台可使用的功能不因未加入而锁定。顶栏分别显示“浏览器到 Worker”和“Worker 到集群”的状态，后者离线不覆盖为整个工作台离线。

## 3. 从 Web 主动加入集群

只有具备本机节点管理权限的登录用户可操作。流程：

1. 填写目标 Server 地址和本节点显示名，检查连接与协议兼容。公网要求 HTTPS，不能因证书失败自动降级 HTTP。
2. 输入由目标 Server 管理员签发的一次性 Enrollment Token；不索取 Server bootstrap 管理员凭据。凭据不进入 URL、浏览器持久存储、诊断日志或分析事件。
3. 确认目标地址、Server 可验证身份及 Team 等可获得的目标信息；无法验证时如实说明，不能仅凭用户输入的名称宣称可信。最终归属由目标 Server 校验 Token 后确定。
4. 明确告知加入影响：允许该 Server 在其授权范围内向节点下发执行命令，可能使用本机 Agent/模型凭据与执行资源；不是仅上传健康指标。展示上报的数据范围和本地执行限制。
5. 确认后，由 Worker 后端完成注册，持久保存节点凭据，再建立控制连接并上报能力；浏览器不负责保存长期 Worker Credential。
6. 分别展示“注册、保存身份、连接、能力上报”结果。仅 Token 兑换成功不能显示全部接入完成。成功后可跳转集群控制台，不携带凭据或自动建立 Server 登录身份。

状态分别记录注册归属与连接健康：未加入 → 正在加入 → 已注册但连接中 → 已连接；另有加入失败、已注册但离线、暂停连接、已撤销/需重新授权。已注册但断网时重试连接，不重新兑换 Token 创建新节点。

注册响应丢失与本地落盘失败需要专门恢复契约：幂等请求身份、可安全核对的结果及待恢复状态。现有一次性 Token 接口是否足够须在实施时核实；不得假设可以无限重用 Token。页面刷新后从 Worker 持久状态恢复流程，不依赖浏览器内存判断是否已注册。

地址探测由后端执行，需节点管理授权、超时、响应大小和并发限制。限制为支持的 HTTP(S) 端点，阻止危险重定向、云元数据等目标；内网地址是正常场景，不采用全禁私网的粗暴规则。不得做成任意 URL 内容代理，也不向未经确认的重定向地址转发 Token。

## 4. 断开、退出与换集群

- **重连**：保留同一节点身份，修复网络/地址问题，不重复注册。
- **暂停连接**：保留绑定，停止接收新的集群命令；不等于 Server 撤销身份，需明确已有执行与日志待补传状态。
- **退出集群**：撤销绑定与后续执行授权，默认不删除本地目录、本地会话或 Agent 凭据。优先排空已接受的集群任务，存在运行/队列时展示选择、影响与确认；强制退出不得把仍运行的任务假称完成。
- Server 不可达时允许本机明确解除信任并禁用旧身份，但显示“远端撤销未确认”，提供 Server 侧清理说明；不能宣称远端记录已删除。
- **更换集群**：先结束旧信任关系，再加入新集群。近期一台 Worker 只绑定一个 Server/Team；同一 Server 的多地址故障切换不等于多集群绑定。

退出、撤销或切换集群都不把旧集群会话自动变成本地会话或新集群会话。保留来源和数据归属；集群会话后续访问/接管另定授权流程。独立会话可继续使用。

## 5. 本地与集群会话边界

- 本地会话不要求 Project，固定绑定本地工作环境、Agent 和模型，由 Worker 本地身份授权。
- 集群会话保留 Project/Workspace/Placement 归属及 Server 授权规则。登录 Worker Web 不自动取得集群私人会话读取或执行权。
- 加入集群只注册节点并上报约定能力，不自动上传本地会话正文、目录内容、历史或密钥。状态与能力上报需说明可能包含的节点元数据。
- 本地会话发布、资源导入、集群会话委派访问及离线继续执行属于后续独立规格；初次交付不自动执行这些操作。
- 同一 Session 只有一个持久队列、Journal 和 Native Session 执行所有者，所有入口经过统一调度；事件记录来源，不制造双份权威历史。
- 集群断线不影响独立本地会话。集群会话新增操作需有效授权；已经接受的操作按明确策略继续或停止，不把断线当作授权永久有效或执行已终结。

## 6. 身份与公网安全

Worker Web 用户凭据、Worker API Token、Server Enrollment Token、长期 Worker Credential 用途分离，不能相互当作登录密码。底层安全工具可复用，但授权策略由宿主负责。

默认安全监听，公网监听显式启用。公网 HTTPS 可经受信反向代理终止 TLS，不强制新增中间件。浏览器采用可到期/撤销的 HttpOnly 会话，公网 Cookie 启用 Secure；具备登录限流、Origin/Host 校验、CSRF 防护、受信代理配置与 SSE/WebSocket 鉴权及撤权处理。所有能力、历史、文件和控制端点均受保护，不仅保护首页。

首批可采用单本机管理员，不等待 M6 完整团队体系；但本机认证与公网安全是 Worker Web 开放的前置条件，不能延后至 M7。长期凭据保护、目录授权与审计随功能实现；操作系统管理员的物理控制权不作为普通 Web 用户越权的理由。

## 7. 可复用 Module 与实施顺序

建议在现有 monorepo 内维护，先形成真实复用，再决定是否独立发布包。Module 通过小 Interface 暴露能力，宿主使用 Adapter 组合；不得为了共享 UI 把 Server Team/Project 权限塞进 Worker Runtime，也不得为了本地入口复制一套 Session 状态机：

| 模块 | 职责 | 宿主保留的职责 |
| --- | --- | --- |
| Agent Interchange Module | Agent Adapter、Provider 会话生命周期、标准事件和终态保证 | 项目、团队、集群注册、HTTP 登录与 transport 重连 |
| Session Runtime Module | 发送、订阅、游标补传、队列、停止、批准、恢复与状态投影 | Server/Worker 连接、认证和资源授权 Adapter |
| Session Surface Module | Composer、时间线、工具、队列、运行详情及 presentation 密度 | 集群项目外壳、画布容器或 Worker 本地外壳 |
| Session Lineage Module | Fork cursor、目标 Session 原子创建、血缘查询和生命周期 | 各宿主的权限策略、路由与布局 |
| Canvas Projection Module | 将获权图读模型投影为节点/边和分级详情 | React Flow viewport、URL、个人/团队布局 Adapter |

契约暴露操作能力与不可用原因，不强迫独立模式提供虚假 Project/Worker 注册 ID。独立安装身份与集群注册身份须分离，本地 Session 的稳定身份不随加入/退出变化。不允许两个独立进程同时写同一个运行时状态库或操纵同一个 Native Session。画布和 Fork 首批属于集群 Project 能力；未来若本地工作台需要本地图，必须通过本地 Host Adapter 复用同一 Lineage/Surface Interface，不复制实现，也不因 Worker 加入集群自动发布本地血缘。

M1 增加双宿主交互和权限设计。M2 增加以下切片，与已有 S1–S6 共用实现，不重建两套聊天：

- **W1 独立启动与身份**：无 Server 配置可启动，持久本地身份、管理员初始化、目录授权与生命周期。
- **W2 本地 Web/API 与共享会话**：在已有 S1–S4 共用能力基础上增加 Worker 连接适配；本地认证、安全访问、Agent/模型选择、持续对话与控制闭环。
- **W3 主动加入集群**：实现本节注册/连接状态、重试、暂停/退出及不泄露本地历史的链路；复用既有 Enrollment，不把不可确认的注册视为失败后盲目重建。

先定 W1 和共享接口，再交付 W2；W3 依赖本地安全管理入口。M4 承接更深入诊断、维护、升级；M6 承接多人和委派授权，不阻塞单管理员工作台。

## 8. 验收场景（待实施）

1. 干净环境安装、不设置 Server，初始化管理员，登录 Web，与已认证 Agent 对话；重启后本地历史仍在。
2. 未认证请求无法读取历史、调用工具或变更集群；公网配置通过 HTTPS、CSRF、Origin、撤权和 Token 泄露检查。
3. 从 Web 加入有效集群，Server 仅看到约定节点/能力；已有本地会话身份不变且正文未上传。
4. Token 失效/过期/已使用、地址错误、证书失败、响应丢失和注册后连接失败分别展示可恢复状态，无重复节点或假成功。
5. 浏览器刷新可恢复加入进度；集群断线时本地会话继续，受管会话不绕过授权。
6. 运行中暂停/退出明确影响和处理方式；离线退出提示远端未确认；退出后独立工作台可用、本地文件未被隐式清理。
7. 两个入口的队列、停止和 Journal 保持唯一性；换集群不共享旧内容；Server 与 Worker Web 使用同一会话模块完成回归。

本文是产品与设计安排。具体路由、命令参数、Schema 迁移和注册恢复协议需在对应切片开工时确定，不据此宣称已提供安装命令或公网服务。
