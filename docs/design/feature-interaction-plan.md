# M1 功能补全与交互设计计划

状态：调研后设计提案，待用户/原型反馈；尚未实现或验收。实施不等待所有后续页面定稿。

依据：[产品方向](../product-direction.md)、[路线图](../roadmap.md)、[Wemux 源码对照](../research/wemux-m1-feature-interaction.md)。本文 S 编号表示 M2 功能切片，不改动产品里程碑编号。与旧交互稿冲突时，以产品方向和本轮确认后的交互规则为准；历史执行不变量继续有效。

已确认补充方向：[Worker 独立 Web 工作台与集群接入](worker-web-workbench.md) 和 [会话协作画布与血缘模块设计](session-collaboration-canvas.md)。以下集群页面设计继续适用；共用会话模块必须支持独立 Worker 宿主，不要求本地会话伪造 Project。W1–W3 与 S1–S6 已完成的双宿主能力作为后续 Session Surface 基础；画布 C0–C6 是新增计划，尚未实施或验收。

## 1. 设计目标与优先级

设计定位：面向开发者和团队的高频工作控制台，克制、清晰、紧凑；沿用现有 Tailwind token、中文文案和 Lucide 图标，不换框架、不引入营销式视觉。

| 优先级 | 功能 | 当前类型 | 安排 |
| --- | --- | --- | --- |
| P0 | Worker 独立启动、鉴权与远程 Web、可选加入集群 | 新目标，需后端及安全闭环 | M2 W1–W3，与 S 系列共用 |
| P0 | 全局/项目导航、会话布局统一 | 已有能力，缺交互整合 | M2 S1 |

## 2. 信息架构

```text
全局导航
  项目（默认入口，最近项目与继续工作）
  集群
    节点 / Agent 与模型 / 诊断
  设置

项目上下文
  会话（列表 / 协作画布 / 专注会话）
  概览
  工作区
  任务（看板 / 列表）
  活动
  项目设置
```

- 项目切换器只负责切项目；会话列表只列当前项目会话，不再多处重复一棵完整项目树。
- “运行时”能力页归集群，旧 `/runtime`、`/runtimes` 深链接保留兼容，不让能力清单散落两套导航。
- 项目会话入口默认恢复该项目最近仍可读会话；没有时显示本地新对话草稿。显式“新对话”永远进草稿，不自动恢复旧会话。
- 最近访问仅是客户端偏好，按 Server 连接身份、用户、项目隔离；权限变化后重新校验。无效深链接明确报错，不静默跳第一项。
- 会话/任务/工作区实体选择属于 URL；筛选适合查询参数。详情开关、折叠和宽度是视图状态，草稿不放 URL。画布 active Session、canvas/focus Presentation 和可分享的局部图进入 URL；节点位置、viewport 与草稿属于布局/视图状态，不作为领域身份。
- 保留现有实体路由。若新增 `/projects/:id/sessions/new`，需防止被当作 sessionId 解析并验证路由优先级，不在调研中直接改路由。

Worker 独立宿主使用“会话 / 本地工作环境 / Agent 与模型 / 集群连接 / 设置”；未加入集群时不强制登录 Server 或创建集群 Project。集群连接采用主动加入向导，分别显示注册与连接状态，具体行为遵循 Worker 工作台设计。下方布局是集群宿主，共用对话区不直接依赖该导航。

## 3. 会话工作台区域分工

```text
全局栏   项目切换 / 当前页面                    连接与设置
项目栏   会话列表             主工作区                      可选详情
会话     [新对话] [搜索]      标题 / 执行配置摘要             执行位置
概览     最近 / 状态筛选      必要异常提示                    模型与能力
工作区   工作区 A             对话与工具时间线                用量
任务       会话 1             回到最新消息                    同步与诊断
活动       会话 2             队列预览（有内容才显示）
设置     工作区 B             输入框 [发送] [停止当前执行]
```

- 桌面左侧可折叠，默认保留可发现的会话切换入口；右侧详情按需打开，不常驻占满对话空间。
- 工具运行显示名称、状态、摘要；参数/完整输出展开查看。失败优先展示原因，长输出有明确截断/展开，不静默丢内容。
- 阅读旧消息时新输出不抢滚动位置，提供“新消息/回到最新”；切换会话保留草稿与合理滚动位置。
- 输入自动增高且有最大高度；运行期间可编辑和提交后续消息。Ctrl/Cmd+Enter 与桌面 Enter 规则保持现有习惯，中文输入法 Enter 不触发发送。
- 用量分输入、输出、缓存、总量、费用；缺失标“未报告”，部分数据标“部分”，避免把不同统计范围混加。
- 手机默认单主区：列表 → 会话 → 详情；输入区不被软键盘遮挡，队列可折叠，停止与发送都有可触达入口。抽屉关闭恢复触发点焦点，图标按钮必须有中文名称。

## 4. 关键交互规则

### 4.1 新建与首条消息

1. 点“新对话”仅创建本地草稿，不产生远程空会话。
2. 预填有效的最近执行组合，或唯一候选；有多个候选且无偏好时要求选择，不偷偷挑第一项。
3. 选择 Workspace，再选择已存在的 Placement/Worker，再选该 Worker 的可执行 Agent 和模型。
4. 无 ready 副本时给“准备工作区/执行位置”，保留草稿；ready 前不把聊天排进物化流程。
5. 首次发送创建 Session，保存原 requestId。Session 身份确定后进入它的时间线，再跟踪首条消息原 commandId/messageId。
6. 创建结果未知时保持身份核对；创建成功、首条消息失败时在同一会话重试，不能再建一个 Session。
7. 不复用旧首条消息来开始第二个新对话；显式新建产生新草稿/请求身份。

新建与已有会话共用输入视图和键盘规则，创建控制器与发送控制器仍各负其责，不强行合并为复杂大状态机。

### 4.2 执行位置与绑定

- Workspace 不是节点；选中 `(workspaceId, workerId)` 对应的 Placement 后，状态、路径与可执行性均取该副本。
- 其他副本失败不禁用当前就绪副本；同名 Agent/模型不能跨节点推断可用。
- 已有 Session 的 Worker/Agent/Model 是绑定信息；提供“以此配置新建”，不静默重绑。
- 运行时 `set_model` 当前接口与固定绑定语义存在冲突，先另写裁定，首批不暴露普通切换按钮。
- 同一 Placement 的会话共享文件；新会话隔离对话上下文而非文件。需要文件隔离时新建工作环境。

### 4.3 提交、队列和停止

| 状态 | 用户看到什么 | 允许的动作 |
| --- | --- | --- |
| 草稿 | 可编辑内容 | 发送，或离线时继续编辑 |
| 请求提交中/结果未知 | 正在提交/正在核对，不宣称已执行 | 继续编辑新草稿；同一不确定请求按原身份核对/重试 |
| Worker 已持久入队 | 排队位置和内容预览 | 逐条取消，等权威确认，不立即删除伪装成功 |
| Turn 执行中 | 回复与工具事件 | 继续发送下一条、停止指定当前 Turn |
| 停止中 | 请求已发出，尚未确认执行终结 | 继续观察，不因 accepted 就显示完成 |
| 已取消/失败/完成 | 对应终态与必要原因 | 显式新发起或恢复，不把取消等同发送失败 |
| 离线/历史不完整 | 缓存、新鲜度与操作限制 | 可读历史和写草稿；受权威 capability 约束执行 |

停止仅针对点击时的 Turn；若已结束，不误停后续 Turn。取消队列与开始执行竞态必须给出已开始/无法取消的真实结果，并允许用户明确停止该 Turn；不得自动清空队列。

Task Run 页面继续区分“取消 Run”与“停止 Turn”。后续独立消息不属于前一个 Run，不延长其生命周期。

首批不提供队列排序、编辑、发送全部或清空全部。后续编辑需先定义原子修改或确认取消后重新提交契约。

### 4.4 查找与名称管理

- 保留按 Workspace 分组；补状态筛选、最近访问、清晰的无匹配态。
- 当前只承诺当前授权项目范围搜索，不称为全局历史全文搜索。
- 重命名用现有 PATCH；保存中防重复、失败保留名称草稿、成功同步标题/列表/详情。
- 归档和删除是不同操作；首批不以删除代替归档，不因归档自动停止运行或清理文件。
- 跨刷新保存草稿若采用浏览器存储，须按连接/用户隔离，退出可清理并提示共享设备风险；本地草稿不是可靠消息队列。

| S4 队列和停止闭环 | Web client、Session 控制 HTTP/application、Worker 既有命令、会话状态投影与 UI | 依赖 S3；增加当前 Turn 与队列条目权威数据、操作能力、requestId；不复用 DELETE command 假充已入队取消 | A 运行/B/C 排队，取消 B 后 C 保留；停止 A 不误停 C；竞态/断线不假成功；未授权会话拒绝控制 |
| S5 时间线与运行详情 | TimelineEntry、Journal 投影、ContextPanel/运行详情；工具折叠、用量、回到最新 | 复用现有 Journal/SSE，不制造第二份历史；依赖 S1，队列字段接 S4 | 长工具输出可读；失败醒目；阅读历史不抢滚动；未知用量不显示为零；Run 复用不回归 |
| S6 会话查找和重命名 | Sidebar、查询状态、client PATCH、列表缓存 | 复用现有 update；依赖 S1；最近访问只是客户端偏好 | 筛选无匹配不当空项目；改名各处同步；失败保留草稿；已失权最近会话不暴露内容 |

S1–S6/W1–W3 已完成的会话与双宿主能力继续作为运行时基础。画布不得复制这些控制器；C3 只增加新的 Presentation 和容器切换。

### S4 开工前必须确定的数据

- activeTurn：turnId、状态、开始时间；无法确认时明确 unknown。
- queue：messageId、submissionCommandId、顺序、内容摘要、状态；逐条取消绑定真实命令而不是列表序号。
- control capabilities：是否可停止/取消及原因；不能仅用 Worker online 计算授权。
- 事件关联：Worker 先落盘再上报，Server 投影遵循序号；有缺口时不能把队列推断为空。
- 操作幂等：同 requestId 不生成不同停止目标，响应丢失可核对结果；任务 Run 取消仍保留其独立边界。

## 7. 后续页面设计任务

### M3 项目与环境

先画项目概览的“继续工作/运行中/待审查/环境异常”，再画 Workspace 列表与副本详情。每个副本单独显示 Worker、状态、路径和重试。添加 Placement 的 Web 路由与实际 handler 要补齐后再开放按钮；明确稳定 requestId。多仓库、文件树与 Git 面板分别排规格，不阻塞基本多节点管理。

### M4 集群与能力

以节点列表 → 节点详情 → 能力/模型/诊断为路径，注册引导分安装、注册、连接、能力上报。运行时清单归集群；命令交付表成为诊断页，不作为日常主界面。未安装、未认证、仅检测、可执行分别说明；管理操作必须有实际结果，不暗示刷新列表会重新扫描 Agent。

### M5 任务与结果

保留看板/列表及现有 Review，优先结果摘要、运行快照、证据和要求修改。Task 页复用会话组件。评论/@/通知直到 M6 权限闭环后开放，避免借鉴参考项目时把任务变成强制聊天桥。

## 8. 原型设计与评审安排

按以下三个批次推进，不先画十几个互不关联的静态首页：

1. **第一批：双宿主导航与会话**。桌面新对话、运行中、队列展开、工具详情、已有会话详情；手机列表/会话/详情；Worker 独立登录、目录选择与暂不加入集群。
2. **第二批：环境与集群**。A ready/B failed 的同一 Workspace；Worker 详情、能力失效、注册进度；Worker Web 主动加入、已注册但离线、重试和退出确认。
3. **第三批：任务与审查**。指派 → 执行 → 要求修改 → 新尝试 → 批准，清楚表达独立消息与 Run。
4. **第四批：会话协作画布**。摘要图、Fork point、画布内对话、执行中最大化/缩回、手机血缘树、权限受限节点；必须使用真实图 DTO，不用手工静态边冒充原型已验证。

每批原型标注：已有能力、需接线、需新能力。可用同一组数据：一个项目、两个 Workspace、三台 Worker、Pi/Claude 可执行和一个仅检测 Agent。不要将演示状态当真实探测结果。

用户原型尚未提供时可按本文线框开始评审；到稿后只比较布局、导航成本、状态可理解性和触屏操作，记录采纳/调整原因。关键评审点：

- 项目默认进入继续会话还是概览？本提案为继续会话，概览显式可达。
- 桌面默认保持可见的会话列表还是专注模式？本提案保持列表，可折叠。
- 首批是否接受不做终端/附件/队列编辑？本提案先交付完整文本与控制链路。

以上是待确认设计选项，不反复询问已确定的轻量架构或双路径定位。
