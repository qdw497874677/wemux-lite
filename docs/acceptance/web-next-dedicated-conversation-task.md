## 合同与实现

- `POST /api/sessions` 不再新建无 Task 的 Session。完成当前用户、Project、Workspace ready Placement、Worker、Agent、Model 校验后，在同一事务自动提供专用 Project Task。旧调用方无需增加 Task 字段。
- 专用复用键为用户 + Project + Workspace + Worker + Agent + 场景。场景可为 `quick-chat`（省略时默认）或 `agent-test`，Model、标题和 Session requestId 不进入复用键。同键可以创建多个 Session。
- `apps/server/src/application/dedicated-conversation-task.ts` 以固定有序元组的 SHA-256 生成命名空间 ID，持久化完整身份并在复用时比对。Task、task.created 活动、Session、command、原创建收据均使用既有事务。已删除专用 Task 返回 410，不默默新建同身份替代品。
- 专用 Task 不抢占 Workspace binding、不产生 Run、不更改既有任务指派；Session 保持 owner-only。它不授予平台协调或跨项目派发权限。本增量暂用既有 Project Task 存储与 backlog 状态，不声称已提供专用对话 active/waiting 状态机或运行时讨论权限约束。
- 新请求不可注入 taskId/ownerId；已有 Task Session 路由继续使用显式 Task 合同。Server 固定 Task/Run 归属，用户不能日常换绑。
- Fork 创建目标时显式携带来源 Task，即使选择另一个 Workspace 也不触发新专用 Task。此处只修复新自动绑定逻辑的影响，不代表 Ticket09 分享/Fork 全验收。历史无 Task 来源仍由旧兼容规则处理。普通显式 Task Session 创建校验专用用户、Workspace、Worker、Agent，模型可变化，创建默认 owner-only；不匹配返回 409 及可操作说明。跨环境例外只经内部 Fork 血缘入口，不是客户端可传的豁免。
- 历史无 Task Session 的审批回执读取与重放仍可用。测试显式插入独立 legacy fixture，不通过生产更新解除新 Session 的不可变归属。没有迁移或删除任何既存应用数据；复审修复在自动分配 Task 前核对旧根创建回执，兼容 absent/null 历史归属；重验当前权限及生命周期，原体重放返回同 Session/command，不分配新 Task，不修改历史归属，异体及场景变更仍冲突。
