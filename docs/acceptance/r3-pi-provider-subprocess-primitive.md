# R3 Pi Provider 子进程隔离原语（部分完成）

`apps/worker/src/agents/pi-runtime-session-adapter.ts` 为显式 `RuntimeSessionOpenInput.piProvider` 实现受限进程级配置：临时目录 0700、`models.json` 0600、仅一个 `openai-compatible::model`、进程环境仅有限 `PATH/LANG/HOME/PI_CODING_AGENT_DIR/OPENAI_API_KEY` 加受信任的 WEMUX capability 上下文。明确拒绝 Pi native resume、任意模型切换、额外 Provider key、非 WEMUX 的 launch 环境；不读取用户 `auth.json`/设置/扩展。这是**有意隔离**，不同于普通 Pi Session 的功能继承。关闭或进程异常后回收目录，替换 Session 可用新凭据重建进程；不会把 Secret 写入 `models.json`。子进程在 stderr 中输出原 Secret 的测试先红后绿，失败信号将其替换为 `[redacted]`。还发现 stdout/RPC 正文可原样回显 Secret 并流入 Session Journal：Provider 模式改为每个 Turn 最多缓冲 1 MiB 信号，检查所有输出字符串（含跨 delta 拼接）后才发布；命中时只产生脱敏失败，不发布包括 native Session 引用在内的该 Turn 输出。普通 Pi 模式仍保留原流式事件。缓冲意味着 Provider 模式暂不实时流式显示，达到上限会失败；这是防泄露限制，不能宣称可识别任意变形/编码的 Secret。

离线可复跑：`node --import tsx --test apps/worker/test/runtime-session-adapters.test.ts` 18 pass，`npm run typecheck` 通过；stdout 防泄露变更后独立 `npm test` 通过：Node 856 tests / 849 pass / 0 fail / 7 skip、package 10/10、Web 291/291（`/tmp/pi-provider-output-full-test.log`）；`npm run typecheck` 通过（`/tmp/pi-provider-output-typecheck-fixed.log`）。`apps/e2e/pi-provider-offline.test.ts` 还用本机 Pi 0.87.1 无 prompt 确认单模型配置可被读取。均不证明真实模型认证。

**未完成的边界**：此原语尚未从 `WorkerRuntime` / `ResourceReconciler.providerForLaunch` 自动获得受权 binding 与本地凭据；目前生产 Session 创建也不会设置 `piProvider`，所以资源投影继续 `credential-required`，不能报告 ready。下一切片必须在每次 Turn/Session 打开前重验权限和凭据 revision，处理已存活进程的轮换、撤权、断线重连，明确模型探测与真实 API 错误分类；只有明确授权后才允许可能计费的请求。Pi adapter 的 `piProvider` 输入只能由可信 Worker 组装，不能直接来自 Server JSON、Web 或客户端。详见 `docs/design/r3-pi-provider-process-materialization.md`。
