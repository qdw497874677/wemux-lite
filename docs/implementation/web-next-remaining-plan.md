# Web Next 剩余实施计划

## 执行方式

按用户最新要求，主会话负责实现、测试与验收；子代理只作只读审查。保留已有未提交改动。下述是剩余计划，不是完成证明。

## 收口顺序与关闭条件

1. **04 会话纵向流程**：先关闭审批来源冲突，复用可靠控制请求接入批准/拒绝；补足审批超时与终态恢复，模型变更幂等及下一 Turn 不可变快照，接入 Next 操作。自动专用 Task 与旧入口适配同批收口。关闭条件：公开 API、真实 Worker、桌面/手机浏览器完成创建、发送、取消/停止、审批、模型变更、刷新恢复；原生 Runtime 和付费权限单列，不能用合成事件替代。
2. **05–08 协作执行**：统一获权项目查询 API 与运行时入口；先落实协调模式真实执行限制，再开放协调 Task；版本计划、具体版本授权及原子幂等交接；任务启动、提交与多阶段审查；验证每个可用 Runtime。关闭条件：讨论→计划→授权→普通任务→执行→提交/审查完整链路与越权负测。
3. **09–12 完整资源操作**：Session 共享与同 Task Fork；文件/Diff/终端/成果；Worker/Skill/Preset/Provider；Connector/Channel。复用已有应用服务，不造第二套权限。关闭条件：每项操作具有真实后端路径、失败恢复、权限撤销及移动端交互证据。
4. **13–14 Worker 独立宿主**：本地 Task 与会话固定绑定，复用新版界面与本地鉴权；设置与主动加入/退出集群。关闭条件：断开 Server 后仍能操作，重启持久化且不上传本地会话。
5. **01–03、15–16 总体验收和切换**：逐操作对账，补现有票据未闭环项；跨页及双宿主全回归，再移除兼容和旧前端。不得提前删除旧版。Google/SMTP、真实原生认证、外部写入与付费调用未具条件时明确阻塞，不虚报完成。

## 批次执行规则

- 每批覆盖完整行为链，先核对接口、身份、状态转换和恢复规则，再改配套层；不再为每个文件单独委派实施。
- 测试红绿、相关回归、真实浏览器验收分别记录；独立审查集中处理具体缺陷。
- 票据在综合验收条件满足前保持 partial。测试数量不代替交付比例。
- 不擅自部署、覆盖全局运行时、清理他人数据或发起付费/真实外部副作用。
