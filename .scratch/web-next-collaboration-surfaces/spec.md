# 会话协作界面：画布、文件与终端、成果、连接器（NEXT-09、NEXT-10、NEXT-12）

Status: ready-for-agent

## Problem Statement

仓库已有会话、文件、连接器等基础和部分授权路径，不能笼统宣称全部缺失；缺口须按操作盘点并补全新版入口与完整生命周期验收。协调入口仍关闭，工具网关与命令授权尚有已知缺口，不能说写通道已全部可靠关闭。

作为获权实施用户，我想在会话里安全地读写文件、看 Diff、用终端并下载成果；作为审查者，我想引用成果而不复制现场；作为 Team 成员，我想按授权配置连接器、审批外部写入并处理投递失败。

## Solution

1. **画布与 Fork**：按会话权限共享与访问画布；同 Task 下可固定 cursor Fork 并保留血缘；撤权后列表、血缘、缓存与实时流同步过滤。
2. **文件、Diff 与终端**：获权实施用户可浏览、修改文件、查看 Diff、使用终端、下载成果；协调模式永不取得实施写权；终端有创建、重连、关闭与清理的完整生命周期。
3. **成果与审查引用**：成果可阅读、下载并被审查引用；引用不复制执行现场，下载受权限校验。
4. **连接器与渠道**：按授权配置；Secret 写入不回显、不出现在日志、响应与事件；外部写需审批；投递与死信可查，支持幂等重试；撤权立即停止投递。
5. **权限一致性**：列表、血缘、缓存、实时流与下载全部以服务端权限为准，撤权后停止后续提供并清理当前受控客户端缓存；不能回收用户已下载或自行保存的数据。

## Implementation Decisions

- 权限以服务端为准：列表、血缘、缓存与实时流共用同一权限投影，撤权后所有出口同步过滤，不依赖客户端隐藏。
- Fork 固定 cursor 且同 Task；血缘为独立投影，不修改原会话历史。
- 文件与终端能力只对获权实施用户开放；协调模式的工具面不包含文件写入与终端，且该不变式在权限投影中强制。
- 终端生命周期包含创建、重连、关闭与资源清理，异常退出后不留下悬挂进程。
- 成果以引用形式被审查使用，下载受权限校验；不复制执行现场。
- Secret 只写不读：写入后接口、界面、日志与事件都不出现明文；投递记录只引用 Secret 标识。
- 外部写审批与撤权：审批决定投递与否；撤权后队列中未投递项立即失效。
- 死信重试：平台以稳定投递身份去重；支持外部幂等键时透传并验证，否则结果未知保持待核对，不保证外部 exactly-once。撤权阻断后续投递，不能撤销已外发副作用。
- 连接器调用继续受能力令牌、allowedTools 与资源绑定校验约束。

## 实现计划

1. 01 复用关系与权限投影，补固定 cursor Fork 和血缘查询；真实多用户浏览器验证列表、流与受控缓存撤权清理，已下载副本不列入回收承诺。
2. 02 盘点已有文件/终端服务，补 CAS 修改、路径权限、终端重连清理和成果引用；共享 Placement 的文件行为实测，不拿 Session 私有冒充文件隔离。
3. 03 复用连接器/渠道端口，补配置、审批、撤权、投递结果与死信 UI；明确失败和未知结果分开，不盲重试未知副作用。
4. 后端合同与受控测试可独立实施；新增写能力按自身账号/资源权限与审批验收，不再以协调隔离签收为门，最终界面验收需要 01/02/03 齐备。看板派发另由[任务派发 spec](../web-next-task-dispatch/spec.md)覆盖，画布不是看板替代品。

## Testing Decisions

- 复用现有 seam：web-next 会话界面与投影 API、实时流通道、连接器投递端口、文件与终端执行边界、现有 e2e 骨架。
- 只测外部行为：撤权后各出口不可见、Secret 不回显、审批阻断外发、死信去重与未知结果暂停重试、终端生命周期结束无悬挂、协调对话与普通会话按相同资源授权执行工具。
- Prior art：现有画布与连接器模块契约文档及测试、写通道矩阵探针、会话权限测试。
- 真实浏览器验收覆盖桌面与移动视口的主要流程。

## Out of Scope

- 新的协作形态（白板、语音、实时协同编辑）。
- 付费模型与真实外部渠道签收，见[外部服务与独立验收](../web-next-external-gates/spec.md)。
- 双宿主、迁移与切根工作。
