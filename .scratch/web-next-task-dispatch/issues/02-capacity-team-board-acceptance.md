# 02: 团队容量、看板与恢复验收

Status: ready-for-agent
Blocked by: [需求基线](../../../docs/specs/ai-workbench-requirements-alignment.md) D2 首版规则及未配置默认 1、支持配置上限已确认；合同设计可与 [01](01-placement-claim-dispatch.md) 并行，同候选验收需 01 可用。资源探测复用[资源管理](../../web-next-dual-host/issues/01-resource-management.md)实际能力，不等待无关入退群 UI；本地与集群共用准入验收需[本地宿主](../../web-next-dual-host/issues/02-local-host-enrollment-acceptance.md)路径。

**Spec:** [项目看板与团队远程任务派发](../spec.md)
**What to build:** Worker 真实剩余容量、团队公平使用和看板诊断，完成多用户/多 Worker 的持久恢复与异构机器验收。Server 预约不是 OS 资源限制。

## 实现计划

1. 从 Worker 资源上报及 Runtime 启动边界建立带采样时间的 CPU/内存、配置上限与在途占用；本地/集群共用原子准入，不上传本地会话内容。
2. 按已确认 D2 实现机器管理者设置的并发上限、候选剩余容量比例选机，以及符合条件工作按本次执行安排入队时间先后处理（普通任务进入 todo，接手明确安排）；不引入团队配额或复杂优先级，固定机器忙碌不暗换。不把资源分发并发度当运行槽位；陈旧遥测保守处理，明确何时释放预约。
3. 扩展 ProjectTasks/TaskDetailPanel/TaskRuns 的等待原因、实际机器与成果入口；任务状态、执行状态、在线状态分开展示。
4. 注入 ACK 丢失、Worker/Server 重启、取消与完成竞态、撤权和容量减少，核验恢复账及实际进程计数。
5. 两用户、两 Worker 多任务桌面/手机链路；异构真实宿主单列证据，不以本机桩代替。最后转人工签收。

接手补充（已确认）：in_progress 接手与普通任务统一按本次执行安排入队时间排序，无特殊优先级，不复用旧 Task 的 todo 时间。接手意图持久等待及容量恢复匹配，旧执行未确认停止时显示等待原执行确认，不启动。与 01 联合验证接手请求竞争、旧执行封锁及恢复，不增加整票循环依赖。

## 验收

- [ ] 未配置默认 1 个执行槽位，首次接入无需先填配置；机器管理者可配置上限，配置持久化，非管理者修改被拒，无效值被拒而非当作未配置
- [ ] 本地/集群、普通执行/接手共用上限；验证默认仅准入一个执行、提高配置后按上限准入及重启后配置保留
- [ ] CPU/内存只作监测及选机参考，不自动提高上限，不替代执行准入或捏造资源配额保证
- [ ] 候选优先剩余容量比例高者，符合条件工作按本次执行安排入队顺序处理，普通任务与接手无优先级区别；固定机器忙碌保持 todo，无团队配额或复杂优先级
- [ ] in_progress 接手等待容量时显示原因，容量恢复能重新匹配，重启不丢意图；验证普通任务早入队先安排、接手不借旧 todo 时间插队、不可执行工作不阻塞其他合格候选；重复事件/重启不重排，不以退回 todo 代替
- [ ] 本地与集群竞争不能绕过同一机器执行上限；取消/失败/完成正确释放，未知执行先对账
- [ ] 两用户竞争时 Project/Worker/Session 权限独立，队列元数据不泄露他人私有会话
- [ ] 机器在线但忙碌、能力变化、Placement 未就绪均显示真实原因
- [ ] 失联不自动复制已承接执行；重启后旧预约和旧消息不复活执行权
- [ ] 共享 Placement 的写冲突与跨机未提交文件缺失被发现，不承诺自动同步或文件隔离
- [ ] 同候选 typecheck、相关测试、故障链路及桌面手机浏览器通过
- [ ] 真实异构机器覆盖范围、未覆盖项与脱敏证据记录；未覆盖不整票勾选
