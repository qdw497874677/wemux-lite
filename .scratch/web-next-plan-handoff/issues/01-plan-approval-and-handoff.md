## 实现计划

1. 与派发 01 共用任务管理 Interface，Web/Agent 不绑定具体项目管理数据库或工作流字段；授权、版本和回写语义由合同承担，不暴露外部 SDK 给 Runtime。盘点 `apps/server/src/application/task-service.ts` 与 `capability-service.ts`，补任务更新、依赖/阻塞、启动/取消、结果查询和提交能力，Web 与 Agent 共用授权、CAS、幂等；Team 跨项目查询逐 Project 过滤，不拿 `team:` 锚点冒充 Project。
2. 新增持久 revision/批准/交接记录，不把 Journal 窗口投影当 revision 仓库；任务固定交接版本，新计划不修改旧执行依据。
3. 按 D6 已确认交互分别表达本次工作意图（讨论/制定计划/执行）、项目管理 Agent 职责授权及成果审查，不强制用户先选两种自治授权模式。项目配置管理职责与范围，目标对话和手工入口共用操作白名单及可撤销授权；模式标签不替代服务端权限。持续委托按 D6 已确认的事件触发与暂停范围设计；首版不强制期限/金额预算，以可撤销范围及暂停控制；新增付费服务/扩大授权需确认。可得费用如实显示、不可得标未知，不承诺硬控费；自动截止与金额硬上限不在本次范围。不设置任务自动失败重试次数，单次获权操作可先交付。
4. 测 backlog 暂存、获权创建/迁移 todo、要求先审计划三路，含授权撤销、跨项目越权、重复状态事件、重复启动及部分失败重试；真实浏览器证明状态推进无需第二次入队确认。

## 依赖与成果审查配置

本票实现任务管理侧的依赖关系及审查设置；与派发 01 先共享 Interface 合同，两侧分别实现，不建立整票互相阻塞。

- [ ] 任务完成依赖持久化，Web/Agent 共用获权编辑及查询，拒绝自依赖与循环，越权不泄露前置任务信息
- [ ] 依赖资格带版本及等待原因交给派发合同；前置仍在审查、被取消或删除不冒充完成，其他无依赖任务不被一起暂停
- [ ] 项目可配置默认审查，任务可沿用默认、无需或需要人工审查，并支持适用的多级策略；未配置项目默认时不强制人工审查
- [ ] 设置接口验证管理权限，执行 Agent 不能自行降低要求；执行开始固定有效策略，之后改项目默认不影响在途任务
- [ ] 无需人工审查也须显式提交成果及验收证据；需审查时未批准不能完成或解除完成依赖
- [ ] 行为与真实浏览器覆盖项目默认、任务覆盖、执行后固定、越权降级拒绝、审查前后依赖资格变化

## 项目管理交互（D6）

- [ ] 工作意图、项目管理职责授权、成果审查分别表达，不强制“执行既有任务/推进目标”二选一前置表单
- [ ] 项目可配置管理 Agent 职责和授权范围，用户交代目标后操作同一套任务及依赖；手工看板不依赖配置管理 Agent
- [ ] 讨论/计划/执行的能力限制由服务端合同校验，不以模式标签或提示词冒充只读保障；超范围动作不因对话承诺自动获权

## 显式状态与剩余工作

- [ ] 人、主 Agent、任务执行 Agent 通过同一 Interface 更新获权任务状态、阻塞原因及提交成果，服务端检查各自权限、CAS、幂等和固定审查要求
- [ ] Run 异常或正常退出但未提交任务更新，不自动改判 Task 完成/失败；执行结果独立显示
- [ ] 主 Agent 或获权用户可为独立额外工作创建关联任务，同目标继续则保留原 Task 并按需安排新 Session 接手，带目标、验收要求和来源；必要依赖显式设置，创建不自动完成原任务或改写其下游依赖
- [ ] 复制若提供，仅复用获权输入，不复制执行权/批准/完成记录；重复创建请求幂等，不以异常计数自动生成任务

## 任务进度记录与接手上下文

- [ ] 同一 Task 支持多条 Task Progress Record，获权人/Agent 经同一接口追加、查询；保留作者、时间及适用的 Session/Run 来源，身份由凭据与执行绑定校验，重发幂等
- [ ] 任务详情显示进度历史及获权引用；记录包含进展、剩余工作、问题、成果/验证引用和适用的接续建议，不复制完整聊天，不把最新单条当整个任务的权威结论
- [ ] Agent 写入约定借鉴 Matt handoff：围绕接手目标保留必要上下文、决定理由与下一步，已有资料用引用并脱敏，建议 Skill 不授予额外权限；不要求每条填满所有字段
- [ ] 记录可直接用于原 Task 新 Session 接手，不另存重复交接报告；接手者读取任务与获权记录，原会话/作者/审查要求保持不变
- [ ] 追加记录不自动改变 Task 状态或启动执行；引用读取独立授权，Agent 未提交时不编造记录

进度记录补充合同：派发 01 负责共同 Interface，本文提供记录及冻结审查领域定义；两侧实现前冻结合同而非互等整票。正文发布范围已确认：追加是向获权读取 Task 的人和 Agent 显式发布，读取正文不额外要求来源 Session 权限；不向全实例公开，不自动搬入私有会话内容。来源引用及自动生成的标题/路径/预览独立鉴权，发布入口须说明此边界。追加入口统一输入限制及敏感字段处理，Skill 脱敏只作补充，不承诺自动识别所有自然语言秘密。

- [ ] 幂等键按主体、Task、requestId 定位，同键异载荷冲突，重放重验当前权限；两人/两 Agent 并发追加不覆盖，稳定分页
- [ ] Agent Session/Turn/适用 Run 从可信绑定解析；伪造来源、跨 Task Run 被拒；人类历史引用与作者来源分开，无 Run 的合法 Session 可提交
- [ ] 人和 Agent 能看 Task 即能读已发布正文，即使无来源 Session 权限；无 Task 权限不可读。来源引用及自动预览单独鉴权，撤销来源访问不隐式撤回已发布正文，撤销 Task 访问则拒绝后续读取
- [ ] 人类与 Agent 写入入口说明发布范围，验证敏感字段处理、私有会话不自动搬入及列表/详情预览一致性，不承诺召回已读取内容
- [ ] Adapter 替换及新 Session 接手保留记录身份与原 Task 冻结审查策略，不按新项目默认重算

## 计划与批准

- [ ] 计划保存产生递增、不可变 revision，含创建者与时间
- [ ] 批准绑定具体 revision 与批准人；新 revision 不继承旧批准
- [ ] 界面可查看 revision 列表与批准状态，并可批准当前 revision
- [ ] 重复请求幂等（同 requestId 不产生重复 revision 或批准）
- [ ] 无权限成员不能批准或查看他人无权访问的协调 Task
- [ ] 断言与截图作为证据留存

## 交接与启动分离

- [ ] 交接创建普通 Task，携带计划引用、验收标准与来源引用，可在普通 Task 界面查看
- [ ] 重复交接请求（同 requestId）返回同一 Task，不重复创建
- [ ] 交接为 backlog 时无 Run；获权交接为 todo 或推进到 todo 自动参与派发，分别记录创建/状态迁移/实际启动的幂等结果，失败不重复创建
- [ ] 创建 todo 与后续推进 todo 均检查执行安排权限及适用计划批准，不能通过选择初始状态绕过；重复事件及重入 todo 不复制在途执行
- [ ] 未要求计划审批的获权工作不被批准步骤阻塞；要求审批时严格绑定 revision
- [ ] 项目管理工具可组织任务、查询依赖/阻塞与成果，越界/撤权拒绝且留下实际授权主体
- [ ] 无权限（非成员、无目标 Project 访问权）交接被拒且不留半成品 Task
- [ ] 执行完成后协调上下文可见结果与产物引用，讨论继续可用
- [ ] Run 成功不自动 done，完成按审查策略显式提交
- [ ] 写通道矩阵逐项登记获权项目管理操作，直接实施工具仍拒绝，不使用万能管理令牌
- [ ] 断言与截图作为证据留存
