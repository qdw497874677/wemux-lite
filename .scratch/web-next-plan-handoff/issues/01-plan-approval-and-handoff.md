# 01: 计划修订、批准与交接启动分离

Status: ready-for-agent
Blocked by: [协调入口人工签收与开门](../../web-next-coordination-closure/issues/04-coordination-acceptance.md)。

**Spec:** [计划修订、批准与交接](../spec.md)
**合并来源:** `43966aa` 的原票 01、02。
**What to build:** 打通计划保存为不可变 revision、批准具体 revision、授权幂等原子交接到普通 Task 的完整用户流程；交接只创建，启动必须是独立显式动作。执行结果通过引用返回协调上下文，讨论继续可用。按下面两组检查项顺序实施，不另拆票。

## 计划与批准

- [ ] 计划保存产生递增、不可变 revision，含创建者与时间
- [ ] 批准绑定具体 revision 与批准人；新 revision 不继承旧批准
- [ ] 界面可查看 revision 列表与批准状态，并可批准当前 revision
- [ ] 重复请求幂等（同 requestId 不产生重复 revision 或批准）
- [ ] 无权限成员不能批准或查看他人无权访问的协调 Task
- [ ] 断言与截图作为证据留存

## 交接与启动分离

- [ ] 交接创建普通 Task，携带计划引用、验收标准与来源引用，可在普通 Task 界面查看
- [ ] 重复交接请求（同 requestId）返回同一 Task，不重复创建
- [ ] 交接不自动启动：创建后无 Run，启动是独立操作
- [ ] 无权限（非成员、无目标 Project 访问权）交接被拒且不留半成品 Task
- [ ] 执行完成后协调上下文可见结果与产物引用，讨论继续可用
- [ ] Run 成功不自动 done，完成按审查策略显式提交
- [ ] 写通道矩阵新增"交接允许但受限"行，其余通道仍全拒绝
- [ ] 断言与截图作为证据留存
