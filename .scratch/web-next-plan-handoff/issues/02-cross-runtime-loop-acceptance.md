## 实现计划

1. 沿用 RuntimeSessionAdapter 与同一项目管理 API，按 pi / claude / opencode 能力提供工具入口，不把 test-agent 算作真实 Runtime。
2. 对每个入口跑要求批准/无需重复批准两条闭环，核对用户身份、成果引用、失败/取消和 Run 成功不自动完成。
3. 按 D6，由目标/要求输入、任务完成、审查通过及依赖解除触发相关工作检查，持久化去重、有界处理并在重启后恢复。机器恢复/容量释放归调度器，不必唤醒管理 Agent；首版无无事定时巡检。用户暂停阻断新增管理安排，取消在途执行另行明确操作；恢复事件不得绕过暂停或复活失效授权。主 Agent 对照目标与成果，通过同一任务接口为独立额外工作创建关联 Task，同目标安排原任务继续/接手，并明确更新状态；不使用任务失败计数或平台无进展推断驱动重试。验证授权与暂停作用域：受影响管理工作停止新增安排，独立获权工作可继续；不强制期限/预算，不引入金额硬上限。
4. 同候选浏览器与真实运行证据逐 Runtime 列表记录，未覆盖仍未完成；最后转人工签收。

## 分项验收合同

A 为既有 NEXT-06/08 的跨 Runtime 交接闭环及同候选证据；B 为新增持续自主推进。两者分别记录候选、证据、人工签收人与结论，A 不依赖 B 或新增多候选派发。D5 已确认 B 纳入本次切换；只要求 A 的基础工作仍可先行，但 B 未验收则本次整体迁移和切换不能签收。不得因 A 签收关闭整票或宣告整个 spec 完成。

## 跨 Runtime 闭环（分项 A）

- [ ] 至少一个有效 Runtime 真实执行完成查询 → 交接 → 执行 → 报告，证据含命令与输出
- [ ] 同一流程在其余有效 Runtime 上以各自入口执行，差异（能力、入口形态、认证）明示
- [ ] 执行失败或取消在协调上下文可见并带原因
- [ ] 交接与启动过程留审计记录（主体、目标、revision、来源）
- [ ] 未覆盖项与限制如实标注，不冒充已覆盖
- [ ] 不调用付费模型；使用本地或免费模型

## 同候选验收（分项 A）

- [ ] `npm run typecheck` 与 server / worker / web-next 测试同候选全绿
- [ ] 三个 e2e 同候选退出码 0（协调入口、重连配对、写通道探针）
- [ ] NEXT-06 验收条件逐项核对：按需 revision 批准、授权幂等一致交接、讨论继续可用
- [ ] NEXT-08 验收条件逐项核对：各 Runtime 同一流程、差异明示、真实执行验证
- [ ] 脱敏验收摘要入 `docs/acceptance/`，原始证据留 `.scratch/`
- [ ] A 的未过项如实标注为未完成，登记缺口与责任票；不得以局部证据签收 A

## 持续自主推进（分项 B）

- [ ] D6 首版授权、事件触发、持久恢复及暂停/停止范围实现，无期限或金额预算也可委托
- [ ] 新增付费服务/扩大授权须确认，不把无金额硬上限解释为无限权限；可得费用如实展示，不可得标未知而非零，不宣称严格控费
- [ ] 自动截止时间与金额硬上限明确为后续范围，不因缺少它们阻塞本次验收；真实付费调用仍需单独授权
- [ ] 通过同一任务图在项目职责授权内拆分、建立依赖、跟进阻塞/结果，不要求逐任务选择自治模式；超范围或用户停止即阻断后续动作，运行合同未补齐并验证时不勾选
- [ ] 目标/要求输入、完成/审查通过/依赖解除仅触发相关工作；机器/容量事件由调度器处理，无无事定时巡检或自写事件无限唤醒
- [ ] 暂停管理 Agent 停止新增安排，取消在途执行需独立明确操作；界面说明已有 todo/在途执行的区别，重启及事件重放不绕过暂停
- [ ] 执行 Agent 追加任务进度记录后停止，用户明确提出接手要求后主 Agent 读取记录并在原 Task 安排其他 Agent 的新 Session 接手；确认旧执行停止/对账、准备文件现场，原审查策略不变，记录不等于迁移文件或会话
- [ ] 同任务接手与额外工作新建 Task 分开验收；多条记录可追溯，越权引用不泄漏
- [ ] 执行 Agent 写回进展与困难，不主动发出接手请求或选择接手者；主 Agent 或获权的人独立决定并提交接手安排，不要求执行 Agent 先请求。普通记录追加或 Run 退出不因此自动唤醒管理 Agent，不以隐式轮询补齐
- [ ] 依据成果识别独立额外工作并创建关联任务有真实链路证据；Run 未更新任务时仅显示执行事实，不自动重试或改变任务状态
- [ ] 重复事件、重启、未提交状态更新及撤权有行为证据；涉及新增多候选派发时引用派发 02 的真实验收
- [ ] B 独立人工签收，作为已确认 D5 的本次切换前置；不随 A 签收消失
