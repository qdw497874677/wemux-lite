# 备份、重置、切根与旧版删除（NEXT-16）

Status: ready-for-human

## Problem Statement

只有 NEXT-01–15 全部通过后才能切根，但切根本身没有可重复的 runbook：备份哪些数据、如何成组停服、重置哪些应用数据/身份/传输状态、如何演练恢复、如何切根并删除旧版、回退怎么做，都还是口头约定。破坏性操作一旦做错会丢外部仓库、工作区源码或 Agent 全局认证。

作为操作者，我想有一份可重复执行的 runbook，在目标实例上清点备份、演练恢复、切根并删除旧版，同时通过构建、测试、打包与真实双宿主验收。

## Solution

1. **备份与重置 runbook**：成组停服、备份 Server 与 Worker 应用数据/身份/传输队列；明确不触碰外部仓库、工作区源码与 Agent 全局认证；恢复演练可重复执行。
2. **干净实例全链路验收**：在重置后的干净实例上完成注册、邮件、Worker 入群、对话、协调、交接、协作界面与双宿主流程。
3. **go/no-go 与切根**：在 01–15 全过后固定候选，切根、删除旧版与构建依赖、跑全量构建/测试/打包冒烟，并演练回退。

## User Stories

1. 作为操作者，我想 runbook 明确列出需要备份与重置的数据范围。
2. 作为操作者，我想成组停服，避免备份与写入竞争。
3. 作为操作者，我想重置只影响应用数据、身份与传输状态。
4. 作为操作者，我想外部仓库、工作区源码与 Agent 全局认证不被误删。
5. 作为操作者，我想演练一次恢复，确认备份可用。
6. 作为操作者，我想在干净实例上完成全链路验收。
7. 作为操作者，我想 runbook 参数化目标实例，不写死地址与路径。
8. 作为操作者，我想 go/no-go 依据 01–15 的实际状态判定。
9. 作为操作者，我想切根后新版成为唯一入口。
10. 作为操作者，我想删除旧版与旧构建依赖后全量构建通过。
11. 作为操作者，我想打包与冒烟验证通过。
12. 作为操作者，我想演练回退，确认出问题可退回。
13. 作为操作者，我想破坏性步骤执行前有明确确认点。
14. 作为操作者，我想每一步都有可复查的日志与输出。
15. 作为操作者，我想失败时停在安全状态而不是半切根。
16. 作为操作者，我想验收摘要入库、原始证据留 `.scratch/`。
17. 作为维护者，我想切根与删旧版不引入新的功能改动。
18. 作为用户，我想保留数据有可恢复备份；经逐项确认的应用数据重置与意外丢失明确区分，外部源码与全局认证不被删除。
19. 作为维护者，我想本 spec 的验收结论明确区分已实现、已验证与未完成。
20. 作为操作者，我想真实双宿主验收在切根后仍通过。

## Implementation Decisions

- runbook 为可重复脚本或清单，目标实例、路径与凭据参数化；破坏性步骤标为人工确认点。
- 备份与重置范围显式枚举：Server 数据库与出件箱、Worker home（凭据、传输队列、身份、workspace 元数据）；明确排除外部仓库、工作区源码、Agent 全局认证。
- 停服为成组操作，先停 Worker 再停 Server，恢复时反向。
- 恢复演练必须在重置前完成并留证据；开发期命令授权票不再交付生产旧备份对账能力，切根前须另行实现并验收，不能以干净开发实例替代。
- go/no-go 依据 NEXT-01–15 与 D5 确认的新增范围真实状态，未过项不进入切根；D5 已确认范围不再作为待决项，但范围确认不是操作授权。
- 切根后旧版与旧构建依赖删除，全量构建、测试、打包与冒烟通过；回退演练给出明确步骤。
- 切根不引入功能改动，只做版本与入口收敛。

## 实现计划

1. 01 可提前准备参数化 runbook 和隔离副本恢复演练，不等待所有功能关闭；真实实例停服/重置须再确认目标和范围。
2. 清点应用库、身份、outbox 及将来新增的派发预约/执行权，恢复时先与 Worker 核对在途执行，禁止备份回滚复活旧执行权或重复派发。
3. 干净实例验收仍等待既有外部门和迁移验收；按已确认 D5，新增派发/容量/重新分配、可替换任务管理 Interface、持续自主推进、loop-in 及单 Worker 平台 Runtime loop-out 完整链路均纳入本次验收。外部项目管理产品集成、同 Session 跨多机及透明迁移不在此次要求内。
4. 02 固定候选、逐项 go/no-go，再经独立人工确认切根/删旧；跑构建测试、pack:check 和恢复/回退演练。任一门未过停止，不在切根票顺修功能。

## Testing Decisions

- 复用现有 seam：Server 启动与数据库路径、Worker home 与身份、备份与恢复脚本、全量构建与打包命令、双宿主验收路径。
- 只测外部行为：重置后干净实例可完成全链路、备份可恢复、切根后旧入口不可达、回退可执行。
- Prior art：现有手工环境启动说明、Worker home 结构与 transport 队列诊断方法、`pack:check` 冒烟。
- 破坏性步骤的真实执行需要人工确认，脚本只准备与演练。

## Out of Scope

- 任何功能开发与缺陷修复（未过项回到对应 spec/ticket 处理）。
- 未获用户确认的第三方数据环境。
