# 02: Worker 命令帧授权校验（含恢复路径）

Status: ready-for-agent
Blocked by: 无。

**已确认策略（用户 2026-10-08 后续确认）:** 每次新的集群副作用启动前在线向 Server 复核当前权限；离线或复核失败则暂缓，不使用旧签名代替新鲜授权，独立本地操作不受影响。Server 持有签名私钥，Worker 在经认证的入群流程固定公钥；密钥更新须经认证并支持持久化轮换，不信任命令帧附带的新公钥。缺少可核验授权的历史队列不得自动执行；备份恢复以显式对账模式暂停集群执行和 outbox 外发，操作员有权核对后才解除。此策略确认不是协调残余风险接受，也不是开门许可。

**Spec:** [协调执行边界收口](../spec.md)
**合并来源:** `43966aa` 的原票 03（仅重编号）。
**What to build:** Worker 命令入口在执行前校验服务端短期授权断言：签名、Worker 受众、命令类型、任务/会话范围与有效期。缺失或无效一律 fail-closed，不产生本地副作用并留审计；重启后的持久命令恢复路径同样校验。本票不开放协调入口。

## 实现计划

1. 在 `packages/wire-protocol` 与 Server 命令签发处定义版本化短期断言、Server 密钥持久化及认证入群时的 Worker 公钥固定/轮换、撤权版本/在线启动前核验合同；先构建共享包。旧协议与已序列化的 Server outbox 缺授权不得静默放行，也不能不核对主体就补签。
2. 先以 `session.enqueue` 实现 Server 持久签发 → 出站重放 → Worker 收帧验签/绑定 → 排队 Turn 延迟启动前在线复核的纵向链路，再覆盖全部有副作用的命令类型。在 `apps/worker/src/application/runtime.ts` 的 receive、initialize 恢复、executeLocal 及 `schedule → run → claimNext → execute` 实际启动边界共用授权校验。排队 Turn 原子持久保留可重验的主体、来源和断言；已接受命令不代表后续副作用已执行。独立宿主使用自身鉴权，不能被集群断言要求误伤。
3. 签名只证明签发时许可；每次新的集群副作用（含排队 Turn、provisioning 与恢复）启动前必须在线复核当前权限，无法联系 Server 不启动。定义撤权与启动并发的判定时点，不能用远程复核后的无界等待冒充持续有效；已执行重放只去重，结果读取重新鉴权。
4. 提供备份恢复的显式对账启动方式：禁止 Agent/工具/provisioning 恢复执行及 outbox 发送，覆盖 cluster-lifecycle 集群和本地初始化；未经可核验授权的旧队列隔离而非自动恢复。定义有权操作员解除流程、队列迁移与密钥轮换/升级顺序，不以正常启动或仅断网充当对账模式，供切根 runbook 使用。
5. 测过期、撤权后队列、恢复启动、重复投递、取消权限和无本地副作用，合法集群/本地路径均通过。

## 验收

- [ ] 无授权断言的命令帧被拒，且无本地副作用（无进程、无文件写入、无工作区变更）
- [ ] 伪造签名、过期断言、受众非本 Worker 的命令帧被拒
- [ ] 来自已删除或已撤权主体的命令帧被拒
- [ ] 未知命令类型被拒（fail-closed）
- [ ] 恢复路径启动新副作用前同样校验，过期或撤权拒绝；已执行命令只去重，结果按当前权限读取，不重复执行
- [ ] 入队成功后前序 Turn 阻塞，期间撤权或断网，后序 Turn 不启动；重启调度同样拒绝陈旧授权
- [ ] 旧备份以对账模式恢复后、解除前进程启动数与外发数为零，含 provisioning、Session 调度和 outbox；正常本地离线运行不误伤
- [ ] 拒绝回执不泄露内部细节，且记录原因码
- [ ] 合法集群命令及经本地鉴权的独立宿主操作可执行，离线不拿旧集群签名启动新副作用，现有 worker 测试全绿
- [ ] 负例测试与断言输出作为证据留存
