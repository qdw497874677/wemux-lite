# 协调执行边界收口（Phase 2 收尾 / NEXT-05）

Status: ready-for-agent

## Problem Statement

Team 级协调 Task 的对话入口当前被"运行时隔离资格门"强制关闭（判定 FAIL），团队无法使用协调讨论；而即便打开，执行边界仍有两处可绕过的写通道：工具执行网关不校验能力声明的 allowedTools 与资源绑定，Worker 命令入口不校验命令帧授权。结果是：协调模式既不可用，也没有可信的执行边界证明。

作为 Team 成员，我想在协调 Task 里讨论、研究与计划，并且能确信这个会话在平台上无法改代码、装依赖、部署或经连接器外联写数据，这样我才敢把需要判断力的讨论放进去。

## Solution

把资格门的标准从"OS 级隔离 + 网络出口收敛"改写为**可真实强制、可探针验证的运行时能力收口标准（受限运行环境，不是 OS 隔离）**，并在执行边界补齐强制：

1. **会话级运行环境作用域**（AgentsMesh 式）：每个协调 Session 的 Agent 进程使用落在会话工作区内的独立 home/配置目录，宿主凭据不注入进程环境，工具能力按只读白名单下发，进程工作目录限定在会话工作区。
2. **写通道强制**：工具执行网关校验 allowedTools 与资源绑定；Worker 命令入口校验命令帧授权、受众与范围；未授权请求一律 fail-closed，不产生副作用并留审计。
3. **门标准改写与重探测**：资格门唯一事实来源改为"平台强制层探针通过 + 六类写通道复核全部拒绝 + 部署者书面接受残余风险"；探针与矩阵同候选重跑通过后由部署者翻转常量，开放受限协调入口。
4. **诚实边界**：验收文档与 UI 一律称"受限运行环境"，不得表述为"已隔离"；宿主文件对 Agent 进程仍可读这一残余风险必须显式记录并由用户签署接受。

## User Stories

1. 作为 Team 成员，我想在协调 Task 里发起讨论、研究与计划，这样我能与其他人对齐方案而不直接实施。
2. 作为 Team 成员，我想协调会话按 Team + 用户 + Worker + Agent 自动创建并长期复用，这样我不必每次重建上下文。
3. 作为 Team 成员，我想重开协调上下文时在原 Task 下新建 Session，这样历史仍可追溯。
4. 作为 Team 成员，我想只有我能向自己的协调 Task 发送，这样别人不能冒用我的 Worker 执行。
5. 作为 Team 成员，我想协调会话能读取、搜索、查询我有权访问的项目与任务，这样讨论基于真实事实。
6. 作为 Team 成员，我想协调会话无法修改代码，这样讨论不会意外改动仓库。
7. 作为 Team 成员，我想协调会话无法安装依赖或改动宿主环境。
8. 作为 Team 成员，我想协调会话无法部署或执行发布动作。
9. 作为 Team 成员，我想协调会话无法经连接器或渠道产生外部写入。
10. 作为 Team 成员，我想协调会话无法经文件工具写文件。
11. 作为 Team 成员，我想协调会话无法打开终端执行任意命令。
12. 作为 Team 成员，我想协调会话无法用能力令牌访问 allowedTools 之外的任何操作，即使工具名被伪造。
13. 作为 Team 成员，我想协调会话无法用资源绑定不匹配的能力令牌（跨 project / workspace / worker / connector revision）执行操作。
14. 作为平台部署者，我想 Worker 拒绝无授权、伪造或过期的命令帧，这样集群连接不会被用来在节点上产生副作用。
15. 作为平台部署者，我想被拒绝的命令不产生任何本地副作用（无进程、无文件写入、无工作区变更）。
16. 作为平台部署者，我想命令恢复路径（持久化重放）同样校验授权，这样重启不能成为绕过手段。
17. 作为 Team 成员，我想协调会话的 Agent 进程不继承 Worker 的宿主凭据环境，这样凭据不会被会话使用。
18. 作为 Team 成员，我想协调会话的 Agent home 与配置写入落在会话工作区内，这样不会污染宿主全局 Agent 配置。
19. 作为 Team 成员，我想协调会话的 Agent 进程工作目录限定在会话工作区，这样相对路径操作不会落到别处。
20. 作为平台部署者，我想资格门依据可强制的收口标准判定，这样我能在不完全隔离的前提下诚实决定能否开放。
21. 作为平台部署者，我想在目标宿主上重跑行为探针并获得退出码与断言输出，这样门的结论有可复查证据。
22. 作为平台部署者，我想门通过后由我改常量发版启用，这样不存在按请求开关或运行期绕过。
23. 作为审计者，我想每次越权拒绝都留下可复查审计（主体、操作、范围、原因码），这样越权尝试可追溯。
24. 作为用户，我想界面明确说明这是受限运行环境而非 OS 隔离及其边界，这样我不被误导。
25. 作为平台部署者，我想越权连接器工具调用被拒并留下拒绝证据（allowedTools 之外）。
26. 作为平台部署者，我想资源绑定不匹配的工具调用被拒。
27. 作为平台部署者，我想伪造或过期的能力令牌被拒。
28. 作为平台部署者，我想缺少授权断言的命令帧被拒。
29. 作为平台部署者，我想受众不是本 Worker 的命令帧被拒。
30. 作为平台部署者，我想来自已删除或已撤权主体的命令帧被拒。
31. 作为平台部署者，我想门关闭时所有入口（包括绕过界面的直接 HTTP 调用）都返回 403 并说明原因。
32. 作为 Team 成员，我想门开启后普通项目 Task 的写能力不受影响，协调专属限制不外溢。
33. 作为维护者，我想同候选下 server / worker / web-next 测试与三个 e2e 全部通过，这样交付可复现。
34. 作为 Team 成员，我想至少一个现有有效 Runtime 上协调会话的只读能力真实跑通，这样收口不是纸面声明。
35. 作为维护者，我想验收文档明确区分已实现、已验证、未完成，并说明残余风险边界。

## Implementation Decisions

- **门标准改写**：资格门仍由单一常量投影出唯一事实来源，不可按请求翻转；verdict 的判定依据改为三项：(a) 平台强制层探针通过（工具网关绑定校验、命令帧授权、能力白名单、进程环境与工作目录作用域），(b) 六类写通道复核矩阵全部为拒绝，(c) 部署者书面记录残余风险接受。reasons、reopenConditions 与证据路径同步改写为新标准；旧的"OS 隔离/网络出口收敛"标准与 A/B 岔路由本次决定取代（保留历史文档，记录替代关系）。
- **会话级运行环境作用域**：协调 Session 的 Agent 启动时提供会话级 home/配置目录（位于会话工作区内），只注入该 Session 的模型 Provider 环境变量，不继承 Worker 进程的其它凭据环境；沿用现有 Pi Provider 启动白名单先例并扩展到全部有效 Runtime 的启动路径。
- **工具执行网关强制**：在现有能力令牌校验之后增加"声明与上下文一致性"校验：allowedTools（只读操作集合）必须包含目标工具；资源绑定（project / workspace / worker / connector / connectorRevision / toolName）必须与当前调用上下文一致；缺省拒绝，返回明确错误码，不执行外部副作用，并记录审计事件。
- **Worker 命令入口强制**：每个命令帧携带服务端签发的短期授权断言（受众=目标 Worker、允许的命令类型、任务/会话范围、有效期）；入口在执行前校验签名与范围；未知命令类型或缺断言一律拒绝；恢复路径持久化授权断言并同样校验，过期即拒绝；拒绝回执不泄露内部细节。
- **协调模式能力面**：沿用现有只读 allowedTools 集合（查询、搜索、计划），不新增写操作；协调会话不得获得文件写入、终端、连接器写、部署与安装能力。
- **资格门与界面**：门关闭时所有入口（含直接 HTTP）返回 403 并给出原因与证据路径；门开启后界面显示"受限运行环境"说明与残余风险边界，不出现"已隔离"表述。
- **残余风险接受**：以仓库内文档记录范围、边界、责任与失效条件（宿主文件对 Agent 进程可读、无内核级出口限制、仅适用于部署者自担风险的实例），由用户签署；不得用于未经确认的第三方数据环境。
- **证据**：资格门行为探针、写通道矩阵复跑、网关与命令帧负例测试、三个 e2e 同候选重跑；脱敏摘要入 `docs/acceptance/`，原始证据留 `.scratch/`（不入库）。

## Testing Decisions

- 只测外部行为：从平台边界发起（HTTP、WebSocket、工具网关、进程启动入口），断言拒绝结果与副作用缺失，不断言内部实现细节。
- 复用现有 seam，不新增：①协调门投影与入口（可用性投影 + 403/200）；②Worker 命令帧入口（含恢复路径）；③工具执行网关（能力令牌 + 上下文绑定）；④Agent 进程启动边界（环境与工作目录作用域）；⑤现有 e2e 探针（写通道矩阵、重连配对、协调入口浏览器）。
- 涉及模块：Server 协调门与命令签发；Worker 命令入口、工具执行网关、Agent 启动路径；web-next 协调入口文案。
- Prior art：现有写通道三态矩阵探针、协调入口浏览器用例、server/worker 既有负例测试（越权、幂等、CAS）。
- 覆盖要求：越权 allowedTools、资源绑定不匹配、伪造/过期令牌、无断言/跨 Worker/过期命令帧、恢复路径、门关闭 403、门开启后普通写不受影响、进程环境不含宿主凭据、Agent home 落在会话工作区、至少一个有效 Runtime 上只读能力真实可执行。

## Out of Scope

- 内核级隔离（bubblewrap、Landlock、netns）与网络出口收敛：本阶段明确不实施（用户决定 L1 only）；因此不得声称 OS 隔离，也不得将本收口用于未经确认的第三方数据环境。
- 独立低权限账号或独立容器宿主方案，以及宿主变更要求清单。
- 付费模型与真实外部运行时签收（Phase 1 外部门）。
- Phase 3 之后的交接、画布、连接器、双宿主与切根工作。
