# 迁移收口与旧版移除条件（Phase 6 / NEXT-15）

Status: ready-for-agent

## Problem Statement

新版功能已覆盖大部分旧版能力，但缺少操作级迁移登记：无法逐操作说明"这一项在新版哪里、证据是什么"。旧根前端与旧 Worker 工作台仍保留无 Task 的兼容业务旁路，调用方可能继续走旧路径，迁移没有真正收口；跨页、跨宿主、跨 Runtime 的授权交叉矩阵与桌面手机全链路也尚未验证。

作为维护者，我想逐操作确认新版覆盖并有证据，让旧调用方转到合法 Task Session 后再移除兼容旁路，这样删旧版不会留下未迁移的调用面。

## Solution

1. **旁路勘察**：定位旧根前端、旧 Worker 工作台及任何无 Task 兼容调用面，形成影响面与调用方清单。
2. **操作级迁移登记表**：把规格 §4 的每行细化到操作级，逐项标注新版入口、证据与状态（已实现 / 已验证 / 未完成）。
3. **旧调用方改造与旁路移除**：让旧调用方通过合法 Task Session 创建与发送，验证转换后才移除无 Task 旁路。
4. **授权交叉矩阵与全链路**：跨页、跨宿主、跨 Runtime 的权限交叉矩阵，桌面与手机全链路验收。
5. **签收**：全部有效功能逐操作迁移完成，旧版具备删除条件。

## User Stories

1. 作为维护者，我想先勘察旧根与旧 Worker 工作台的无 Task 旁路，这样我知道影响面。
2. 作为维护者，我想拿到调用方清单，这样改造有目标。
3. 作为维护者，我想把迁移登记表细化到操作级。
4. 作为维护者，我想每项迁移都有可复查证据，而不是"应该没问题"。
5. 作为维护者，我想登记表明确区分已实现、已验证与未完成。
6. 作为维护者，我想旧调用方改用合法 Task Session 创建与发送。
7. 作为维护者，我想旁路移除前验证旧调用方已完成转换。
8. 作为维护者，我想移除无 Task 兼容旁路后，旧调用方功能不回退。
9. 作为用户，我想跨页面操作时权限判断一致。
10. 作为用户，我想跨宿主（集群与独立 Worker）权限判断一致。
11. 作为用户，我想跨 Runtime 权限判断一致。
12. 作为用户，我想在手机上完成主要流程。
13. 作为用户，我想在桌面上完成主要流程。
14. 作为审查者，我想撤权与删除在所有页面与宿主上同步生效。
15. 作为维护者，我想授权交叉矩阵覆盖读取、写入、下载、终端与外部投递。
16. 作为维护者，我想矩阵中的每个交叉点都有断言或截图证据。
17. 作为维护者，我想旧版在迁移完成前不被删除。
18. 作为维护者，我想本阶段不新增功能，只做迁移与收口。
19. 作为维护者，我想迁移期不要求旧版持续回归，但旧版历史异常不阻断新版票据。
20. 作为维护者，我想同候选下测试与 e2e 全绿。
21. 作为维护者，我想验收摘要入库、原始证据留 `.scratch/`。
22. 作为维护者，我想本阶段结束时给出"旧版可删除"的明确结论或未完成清单。
23. 作为用户，我想迁移期间功能不中断。
24. 作为维护者，我想旧版删除的具体动作留给 Phase 7 执行。

## Implementation Decisions

- 先勘察、后改造、再移除：旁路移除必须以其调用方完成转换并验证为前提，不允许"先删再看"。
- 迁移登记表以规格 §4 行为源，逐项落到操作级（入口、角色、权限、证据、状态），不合并成粗粒度行。
- 旧调用方改造通过合法 Task Session 完成创建与发送，不保留新的旁路。
- 授权交叉矩阵以"权限 × 页面/宿主/Runtime"为轴，撤权与删除必须全出口一致。
- 本阶段不新增产品功能，只做迁移、旁路移除与验收；旧版删除动作不在本阶段执行。
- 旧版历史异常不阻断新版票据，但不得据此跳过迁移证据。

## Testing Decisions

- 复用现有 seam：旧根前端入口、旧 Worker 工作台入口、新版页面与 API、宿主切换路径、现有 e2e 骨架。
- 只测外部行为：旧调用方走合法 Task Session、旁路不可达、权限交叉点一致、撤权后全出口不可见。
- Prior art：现有权限测试、会话创建与发送测试、宿主切换 e2e。
- 真实浏览器验收覆盖桌面与手机视口。

## Out of Scope

- 新增产品功能。
- 实际删除旧版与切根（Phase 7）。
- 付费模型与外部渠道签收（Phase 1 外部门）。
